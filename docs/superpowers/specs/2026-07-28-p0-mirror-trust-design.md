# P0 镜像可靠性与数据可信度实施设计

- 状态：已实施并验证
- 日期：2026-07-28
- 权威来源：[豆图设计台产品规范](../../PRODUCT_SPEC.zh-CN.md)
- 范围：P0 可靠性与可信度

本文是非规范性的实施设计，仅解释如何落实权威产品规范。若本文与
`docs/PRODUCT_SPEC.zh-CN.md` 冲突，以产品规范为准，并先修订产品规范再修改代码。

## 1. 目标

本里程碑让顾客可以直接判断当前图纸的数据是否可信，并让三种不同的“镜像”行为在
数据、界面和验收上彻底分离。

完成后必须满足：

1. 顾客在预览、编辑、材料和导出入口看到同一矩阵派生的行列、总格数、实际用豆、
   空白、颜色数和校验状态。
2. 查看反面不修改矩阵、revision 或撤销历史。
3. 水平、垂直翻转图案修改矩阵并进入撤销历史，同轴执行两次逐格恢复原矩阵。
4. 镜像已有图纸只移动完整网格单元，网格外像素保持不变；带 warning 的检测必须再次
   明确确认，无有效合同的检测不能执行。
5. 取消、失败、迟到响应和连续点击不破坏上一个有效结果。
6. 当前主分支的三个选区越界基线失败被修复，使新增验收建立在全绿前端基线上。

## 2. 非目标

本里程碑不实现制作模式、按行/按色/按拼板进度、智能整理、库存、采购、自定义色板、
多品牌转换或新的导出模板。正式施工图增强属于下一个独立里程碑。

不引入 React、Vue 或新的状态管理框架，不重写现有 Canvas、矩阵模型、FastAPI 路由或
持久工作区架构。

## 3. 当前证据与约束

- `src/domain/project.ts` 已把 `cells` 作为统计和矩阵镜像的输入，并验证
  `sum(perColorCounts) === nonEmptyBeadCount`。
- `src/main.ts` 已区分 Canvas 反面视图与矩阵镜像，但顾客文案和状态呈现还不够明确。
- `backend/app/mirror.py` 已从未修改源图读取完整 cell，并把 cell 整体粘贴到目标位置。
- `docs/PRODUCT_SPEC.zh-CN.md` 第 9.5、10、11 和 18.3 节已经定义镜像与统计核心合同。
- 2026-07-28 基线 `pnpm run test` 共 249 项，246 项通过；三个失败均属于选区部分越界
  的预期与实现不一致，必须在功能改动前独立修复。

## 4. 架构

### 4.1 可信度派生层

在领域层增加一个纯函数，从不可变 `BeadProject` 或其 `cells` 生成
`PatternTrustSummary`。它不缓存独立业务数据，只包含：

```ts
interface PatternTrustSummary {
  rows: number;
  columns: number;
  totalCellCount: number;
  nonEmptyBeadCount: number;
  blankCount: number;
  usedColorCount: number;
  perColorCountSum: number;
  isValid: boolean;
}
```

`isValid` 只有在以下条件同时成立时为真：

```text
perColorCountSum === nonEmptyBeadCount
nonEmptyBeadCount + blankCount === rows * columns
cells.length === rows
every cells[row].length === columns
```

该函数复用现有 `calculateStatistics`，不创建第二套计数算法。预览摘要、编辑材料面板和
导出完成面板通过同一格式化模块消费该结构，禁止各自重新拼装计数逻辑。

### 4.2 镜像命令边界

三个行为保持独立入口和独立状态：

- `查看反面` 调用 Canvas controller 的 `setReverseView`。状态只存在视图控制器，不调用
  `withProjectCells`、不提交 history、不中断导出 snapshot。
- `水平翻转图案` 和 `垂直翻转图案` 调用矩阵命令。命令先从当前项目生成完整目标矩阵，
  再作为单个 history transaction 提交，并重新派生统计。
- `镜像已有图纸` 继续走网格检测和 `/api/grid/mirror`，不进入结构化项目矩阵的
  undo/redo。

矩阵命令完成后必须比较变更前后的网格尺寸、非空豆数、空格数、颜色数及逐色数量。
任何不变量失败都拒绝提交并保留原项目。

### 4.3 已有图纸检测确认

确认页复用现有页面和网格编辑器，不增加第二层 modal。页面固定展示：

- `检测到 C 列 × R 行`
- `网格置信度：高 / 需要确认 / 不足`
- 网格覆盖层
- `调整边界`
- `修改行列数`
- `确认并镜像`

置信度分级只负责界面准入，不新增未经样例校准的数值阈值，也不修改后端检测算法：

- 高：合同完整且后端未返回 warning；用户明确确认后允许镜像。
- 需要确认：合同完整但后端返回 warning；用户必须调整，或在看到 warning 后再次明确确认。
- 不足：边界不完整、尺寸不等距或合同校验失败，前端不持有可提交合同，禁止镜像，只允许
  调整或重新识别。

水平和垂直轴在确认前明确选择。网格外坐标、图例、标题、边框和页面背景不进入移动
范围。

### 4.4 异步状态与失败保护

检测和镜像继续使用请求 token 与 `AbortController`：

- 新请求取消旧请求。
- 执行期间禁用重复提交。
- 迟到成功、迟到失败和取消均不得替换当前可见结果。
- 只有响应通过图片身份、尺寸和合同校验后才成为新的有效结果。
- 失败时保留上一个有效检测合同、覆盖层和镜像结果，并提供可重试的中文状态。

## 5. 顾客界面

### 5.1 可信度摘要

无透明空格时显示：

```text
20 × 21 格 · 420 颗豆 · 8 种颜色
图纸统计校验通过
```

存在透明空格时显示：

```text
总格数 420 · 实际用豆 356 · 空白 64 · 8 种颜色
图纸统计校验通过
```

校验状态使用常规产品语义色，不使用拼豆色板颜色。状态文本保留在可访问 DOM 中，并由
稳定的 `role="status"` 区域在矩阵变更后宣告。不得把内部 revision、schema 或哈希展示
给顾客。

预览、编辑材料面板和导出入口显示同一组数字；移动端收起态只保留一行紧凑摘要，展开后
显示完整校验说明。

### 5.2 镜像文案

顾客界面只使用以下名称：

- 查看反面
- 水平翻转图案
- 垂直翻转图案
- 镜像已有图纸

不得把前三项统称为一个含义不明的“镜像”按钮。矩阵翻转完成状态分别为
“图案已水平翻转。”和“图案已垂直翻转。”。

## 6. 测试与验收

### 6.1 前端领域测试

- 可信度摘要覆盖无空格、有空格、单色和最大合法矩阵。
- 每色数量之和、实际用豆、空白和总格数不一致时稳定拒绝。
- 水平和垂直翻转各执行两次恢复逐格相同的矩阵。
- 翻转前后尺寸、总豆数、空白和逐色数量完全一致。
- 查看反面不修改项目引用、revision、矩阵和 history 长度。
- 矩阵翻转是一个可撤销、可重做的 transaction。

### 6.2 智能镜像后端测试

- 水平和垂直同轴执行两次恢复原始 RGBA。
- 网格外区域逐像素相同。
- 单元内部色号和符号随 cell 整体移动，不在 cell 内翻转。
- 坐标、图例、标题和边框保持原位置与原方向。
- 过期图片、非等距边界和边界数量错误的合同稳定拒绝。

### 6.3 交互与竞态测试

- 带 warning 的合同必须再次明确确认；无有效合同的“不足”状态下主操作不可执行。
- 连续点击只产生一个当前请求和一个有效结果。
- 取消、失败和迟到响应保留上一个有效结果。
- 预览、编辑、材料和导出入口的摘要数字一致。
- 320、390、768、1024 和 1440 CSS px 下摘要、镜像入口和确认操作均可到达。

### 6.4 验证命令

按最窄到最宽执行：

```text
pnpm run test
backend/.venv/bin/pytest backend/tests/test_mirror_api.py
pnpm run typecheck
pnpm run lint
pnpm run build
```

最后通过浏览器实际检查新图纸编辑、反面查看、水平/垂直翻转、已有图纸确认和失败恢复
流程，并在桌面与移动视口留存对照截图。

## 7. 实施顺序与回滚

1. 先修复三个选区越界基线失败，不混入 UI 重构。
2. 在权威产品规范中补齐可信度可见文案、置信度准入和失败保护验收。
3. 增加可信度派生与格式化模块及单元测试。
4. 接入预览、编辑材料面板和导出入口。
5. 收敛三种镜像文案和矩阵命令保护。
6. 加固已有图纸确认、请求竞态和失败恢复。
7. 执行自动化、响应式和浏览器视觉验收。

各步骤保持独立文件边界。若镜像确认页出现回归，可以回滚确认页接入而保留领域统计和
矩阵合同；若可信度摘要布局出现回归，可以回滚表面组件而不回滚数据派生与测试。
