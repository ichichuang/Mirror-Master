# 去背景全屏画布与可靠笔刷设计

## 背景与结论

当前交互式去背景编辑器嵌套在 `preview-canvas-stack` 中。该容器会继续使用拼豆预览网格的宽高比和计算尺寸，而不是源图片的尺寸。移动端还会通过 `--preview-canvas-aspect-ratio` 限制画布高度。结果是 9:16 竖图、超长图和部分窄视口下，去背景画布被错误压缩或裁切，底部工具也会挤占图片操作空间。

后端模型与接口不属于本次故障根因。使用本地 720 × 1280 竖图实测，`/api/image/remove-background/mask` 能返回同尺寸灰度蒙版，`/api/image/remove-background/apply` 能返回同尺寸、带有效透明像素的 RGBA PNG。

本次采用独立全屏编辑层：去背景编辑态覆盖整个预览工作区，不再继承拼豆预览画框尺寸；新增独立、可测试的图片视口状态，负责缩放、平移和屏幕坐标到原图像素的映射。

## 目标

- 横图、竖图、方图和超长图都能在完整工作区内按原始比例编辑。
- 支持适应窗口、100%、按钮缩放、滚轮缩放、桌面平移与触屏双指缩放/平移。
- 任意视口状态下，笔刷落点和半径都准确映射到原图蒙版像素。
- 修复留白误画、手势串状态、撤销被迟到精修结果覆盖等可靠性问题。
- 保留现有主体识别、涂抹去除、涂抹恢复、边缘优化、撤销、取消和完成能力。
- 沿用现有品牌、设计令牌、Phosphor 图标和无障碍状态播报。

## 非目标

- 本轮不实现魔棒、套索、自动选区扩展、羽化或图层系统。
- 不更换去背景模型、GrabCut 精修算法或后端 API 合同。
- 不创建新页面或路由，不改造拼豆预览和裁剪工作区。
- 不在本轮引入新的颜色体系、字体或图标库。

## 产品与视觉方向

### 视觉命题

一个深色、安静、以图片为中心的全屏工作台；界面 chrome 保持克制，产品橙只承担待去除区域、选中工具和主操作状态。

### 内容结构

这是操作型产品界面，不使用营销式 hero。编辑态只保留四个层级：任务导航、核心工具、图片画布、缩放与状态。

### 交互命题

- 进入编辑态时使用 160 ms 的透明度过渡建立空间方向感；减少动态效果设置下不播放该过渡。
- 缩放始终围绕指针或双指中心发生，让目标像素留在用户手下。
- 工具切换、撤销和异步状态使用快速、低幅度反馈；在减少动态效果设置下取消非必要过渡。

## 信息架构与响应式布局

### 全屏编辑层

`preview-mask-edit-view` 从拼豆预览画布的尺寸约束中脱离，成为相对 `preview-layout` 定位的全覆盖编辑层。它占用应用头部以下的全部可用空间，并在进入编辑态时遮蔽预览工具栏、预览设置面板和拼豆画布。

编辑层分为三部分：

1. 顶部任务栏。
2. 中央图片画布。
3. 工具与缩放控制。

### 顶部任务栏

- 左侧：取消/返回按钮、标题“去背景选区”。
- 中部：简短状态，例如“正在对齐边缘…”或“选区已更新”。桌面可见，窄屏通过 `aria-live` 播报并使用紧凑状态。
- 右侧：撤销与“完成去背景”。完成按钮保持主操作样式并始终可见。
- 合成期间禁用会修改蒙版的操作，但画布与当前选区保持可见。

### 桌面布局

- 左侧垂直工具区：涂抹去除、涂抹恢复、笔刷大小。
- 中央画布占满剩余区域。
- 底部中央缩放条：缩小、缩放百分比、放大、适应窗口、100%。
- 工具区使用 plain layout 和分隔线，不堆叠卡片。

### 移动端与平板布局

- 顶部只保留取消、标题、撤销与完成，所有触控目标不小于 44 × 44 CSS px。
- 画布占据顶部栏和底部工具之间的全部空间。
- 底部工具分两行：第一行是去除/恢复与笔刷大小，第二行是缩小、百分比、放大、适应窗口。
- 底部使用安全区内边距，不遮挡图片和完成按钮。
- 单指用于笔刷，双指用于缩放和平移。

## 组件与模块边界

### `maskViewport`

新增纯 TypeScript 模块，职责仅限图片视口：

- 保存缩放比例、平移位置、画布尺寸与图片尺寸。
- 计算适应窗口比例、最小/最大缩放比例和 100% 状态。
- 以指定屏幕锚点执行缩放。
- 执行平移并约束边界。
- 在屏幕坐标与原图像素坐标之间转换。
- 在画布尺寸变化时保留当前观察中心；首次进入或显式选择“适应窗口”时重新居中。

该模块不访问 DOM、不读取蒙版、不发起网络请求。

### `maskEditGesture`

将输入解析为明确的手势状态：

- `idle`：没有进行中的输入。
- `paint`：左键、触控笔或单指笔刷。
- `pan`：空格键加左键、鼠标中键或显式平移输入。
- `pinch`：两个触点共同缩放和平移。

状态转换必须结束或回滚不完整笔画，避免平移、缩放和笔刷产生跨屏长线。该模块只输出意图，真实蒙版写入仍由现有 mask edit runtime 执行。

### 画布渲染

显示画布仍使用一个可见 canvas，按以下顺序渲染：

1. 清除可见画布并绘制深色工作区。
2. 使用 viewport transform 绘制源图片。
3. 使用相同 transform 绘制蒙版高亮层。
4. 仅在指针位于图片显示边界内时绘制笔刷圆圈。

真实 `maskCanvas` 和 `overlayCanvas` 始终保持源图片像素尺寸。缩放和平移从不重采样或修改真实蒙版。

## 坐标与缩放合同

- 初次进入使用 `fit`：图片完整可见，并在画布中居中。
- 100% 表示 1 个源图片像素对应 1 个 CSS 像素；设备像素比只用于可见 canvas backing store。
- 缩放下限为 `fitScale`；缩放上限为 `max(fitScale, min(16, max(8, 1 / fitScale)))`，保证图片至少能放大到 800%，同时把极端大图限制在 1600% 以内。
- 按钮缩放使用稳定档位；滚轮和双指使用连续缩放。
- 指针锚点缩放前后，该锚点下的原图像素保持不变。
- 图片小于画布时居中；图片大于画布时至少保留一部分图片在可视区域内，不允许完全拖出视口。
- `clientPointToImagePoint` 对图片外坐标返回 `null`，不再把留白坐标裁剪到图片边缘。
- 笔刷半径继续以源图片像素计算，再通过 viewport scale 绘制屏幕圆圈。

## 蒙版编辑与异步数据流

### 进入编辑态

1. 用户点击“一键去背景”。
2. 前端请求初始主体蒙版，原拼豆预览保持可见。
3. 响应尺寸通过验证后创建 mask edit runtime。
4. 初始化 viewport 为 fit，并显示全屏编辑层。

### 笔刷与边缘优化

1. 图片内 pointer down 创建蒙版快照并开始笔画；图片外 pointer down 不创建笔画。
2. pointer move 将屏幕点转换为源图像素并写入真实蒙版。
3. pointer up 完成笔画并发起边缘优化。
4. 每次蒙版变更都会增加 `maskRevision`。
5. 精修请求记录它基于的 revision；返回时只有 revision 与当前蒙版一致才可应用。
6. 迟到、被撤销或被后续笔画取代的响应直接丢弃。

### 撤销

- 撤销恢复真实蒙版快照，而不是只修改显示层。
- 撤销增加 `maskRevision` 并使基于旧 revision 的精修请求失效。
- 撤销后重建 overlay，并保留当前 viewport。

### 完成与取消

- 完成使用当前真实蒙版调用 apply 接口。成功后沿用现有 foreground 缓存和重新生成流程。
- apply 期间锁定笔刷、撤销、工具切换和重复完成操作。
- apply 失败时保留编辑器、蒙版、撤销栈和 viewport。
- 取消销毁编辑 runtime 和 viewport，终止所有相关请求，返回进入前的预览状态，不改变活动源图或拼豆矩阵。

## 错误与恢复

- 初始识别失败：不进入编辑态；在原预览上显示可重试的稳定错误。
- 精修失败：保留本地涂抹并清除进行中状态；允许继续编辑或直接完成。
- 合成失败：保持编辑态及所有本地状态，错误在顶部状态区和 `aria-live` 区域同步呈现。
- 图片更换、打开项目、重置或销毁工作区：中止所有请求并拒绝迟到结果。
- 可见画布尺寸为零：跳过本帧绘制；恢复非零尺寸后重新渲染，不重置 viewport 或蒙版。
- 方向变化和断点变化：保留当前观察中心并重新约束平移边界。

## 无障碍与输入

- 顶部标题是编辑态可访问名称；画布 `aria-label` 说明当前工具和基本操作。
- 去除/恢复工具使用 `aria-pressed`；缩放百分比以文本表达，不只依赖图标。
- 所有图标按钮都有唯一、随状态更新的可访问名称。
- 键盘支持工具切换、撤销、缩放、适应窗口、100% 和取消；空格键平移不会触发页面滚动。
- 进入编辑态后焦点移动到标题后的首个工具；退出后恢复到触发去背景的按钮。
- 状态变更通过 `aria-live="polite"` 播报；错误不只依赖颜色。
- `prefers-reduced-motion: reduce` 下取消编辑层入场、工具状态和缩放条的非必要动画。

## 测试策略

采用测试驱动实现。每个行为先添加失败测试，再写最小实现。

### 单元测试

- 9:16、16:9、1:1、超长图的 fit 计算。
- 指针锚点缩放保持源图像素不变。
- 100%、档位缩放和缩放上下限。
- 平移约束与观察中心保留。
- 图片内坐标映射准确，图片外坐标返回 `null`。
- 笔刷源图半径与屏幕半径在任意缩放下保持一致。
- `idle`、`paint`、`pan`、`pinch` 状态转换及取消路径。
- `maskRevision` 拒绝迟到精修结果，撤销不会被旧结果覆盖。

### DOM 与合同测试

- 编辑层不再受 `preview-canvas-stack` 尺寸或预览宽高比限制。
- 顶部主操作和响应式工具在所有支持断点可达。
- 工具 pressed 状态、按钮名称、状态播报和焦点恢复正确。
- 合成期间所有变更操作被锁定，失败后重新启用。

### 集成与视觉验收

- 使用真实 9:16 竖图完成主体识别、涂抹、缩放、平移、撤销与透明 PNG 合成。
- 分别检查桌面、平板、手机竖屏和手机横屏。
- 验证工具栏不遮挡图片、图片不变形、焦点清晰、触控目标尺寸合格。
- 对比修改前后的相同图片与视口截图，确认编辑层真正覆盖可用工作区。

## 验收标准

1. 去背景编辑器占满应用头部以下的工作区，不继承拼豆预览宽高比。
2. 9:16、16:9、1:1 和超长图完整显示且不变形、不被工具栏裁切。
3. 适应窗口、100%、按钮缩放、滚轮缩放、桌面平移和双指缩放/平移均可用。
4. 任意缩放和平移状态下，笔刷落点与原图像素一致。
5. 图片外输入不会修改蒙版。
6. 平移、双指操作与笔刷不会串状态或产生跨屏笔画。
7. 撤销后，迟到精修结果不能重新应用已撤销笔画。
8. 精修或合成失败不会丢失蒙版、撤销栈或 viewport。
9. 完成输出保持源图尺寸，并包含有效透明像素。
10. 现有前端、后端、设计令牌、格式和构建检查全部通过。
