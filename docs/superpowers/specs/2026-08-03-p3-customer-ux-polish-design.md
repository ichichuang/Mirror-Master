# P3 顾客体验收尾设计

## 目标

完成四项非阻断体验改进，使文档、下载动作和移动端设置发现性与当前产品规范一致，同时预防临时审计产物影响正式检查。

## 范围

1. 更新 README 的目标流程，不再要求顾客上传前选择照片、像素画或已有图纸模式。
2. 将导出主按钮统一为“下载…”动作，包括项目 JSON。
3. 在移动端首个有效预览结果生成后提供一次半屏设置引导。
4. 将 `artifacts/` 加入 ESLint 与 Prettier 的全局忽略目录。

不修改拼豆规格卡片文案，不扩展已有图纸镜像或 GrabCut 能力，也不改变导出格式、生成算法、项目合同或部署边界。

## 文档与下载文案

README 的第一个目标流程步骤改为：顾客直接选择图片；打开已保存项目和“更多制作方式”中的镜像已有图纸作为次级入口。照片与像素画继续是上传后的内部自动推荐模式。

导出任务名称继续遵循产品规范中的“分享图片、打印制作、材料清单、保存项目”。实际执行按钮统一使用“下载分享图片”“下载打印制作”“下载材料清单”“下载项目文件”，明确这些操作都会产生本地文件。保存项目任务的辅助说明同步使用“下载可继续编辑的项目文件”。

## 移动端设置引导

首个有效预览结果成功返回时，仅当以下条件全部成立才自动将预览设置 sheet 从收起态展开为半屏：

- 当前处于预览阶段；
- 当前响应式布局是移动端；
- 本页面会话尚未展示或由用户主动发现设置；
- sheet 仍处于收起态。

引导状态只保存在当前页面内存中，与现有编辑器首用提示的会话边界一致。刷新页面后可再次出现，不写入浏览器持久存储。

用户在首个结果返回前点击、拖拽或使用键盘展开过设置，视为已经发现，后续成功结果不得覆盖用户选择。自动展开不转移键盘焦点；现有按钮、拖拽和 Escape 收起行为保持不变。展开后通过已有礼貌级状态播报说明“预览已生成，设置已展开，可调整图案大小、颜色、效果和品牌”。桌面布局不自动展开，因为设置已常驻可见。

返回预览、重新生成、去背景切换以及响应式切换不会重复触发引导。失败结果不消耗引导机会；首次成功仍可触发。

## 实现边界

一次性引导判断放在独立、无 DOM 依赖的小型会话状态模块中，主流程只负责将用户交互和预览成功事件传入，并根据返回值调用现有 `setPreviewSheetState('half')`。不新增 sheet、弹窗、计时器、动画依赖或本地存储。

现有三态 sheet 状态机继续拥有布局、手势和焦点行为。ESLint 与 Prettier 仅新增顶层忽略项，不改变规则集或格式约定。

## 验证

- 单元测试覆盖：移动端首次成功触发一次、桌面不触发、失败不消耗机会、用户先操作后不自动展开、重复成功不重复展开。
- 标记/源码测试覆盖统一下载文案和引导接线。
- 运行受影响测试、TypeScript 类型检查、全量 `pnpm lint` 和完整 `pnpm check`。
- 在移动端视口验证首次成功后的半屏状态、可收起行为和无页面横向溢出；桌面验证设置保持常驻且不发生自动状态变化。
