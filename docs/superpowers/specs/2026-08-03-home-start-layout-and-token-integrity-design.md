# 首页入口稳定布局与品牌 Token 完整性设计

日期：2026-08-03

## 背景

首页的“更多制作方式”使用原生 `<details>` 展开“镜像已有图纸”入口。桌面断点当前通过 `align-content: center` 垂直居中整个首页内容组；展开后内容组高度增加，浏览器会重新计算居中位置，导致标题、上传入口和项目入口整体上移。

同时，`--color-text-on-primary: #f0ffcf` 与 `--button-primary-foreground: #cef1f5` 只存在于生成文件 `src/design/generated/tokens.css` 的手工修改中，没有进入 Token 权威源。因此 `pnpm generate:tokens` 会覆盖这些值，`pnpm check:tokens` 也会报告生成物漂移。

控制台警告 `quick-panel.js:2678 [Violation] Permissions policy violation: unload is not allowed in this document.` 指向一个仓库、依赖和生产构建中均不存在的脚本。应用源码没有注册 `unload` 监听器；现有监听器是用途不同的 `beforeunload`。因此该警告不属于应用构建产物，不能通过修改应用业务代码或放宽 Permissions Policy 来消除。

## 已确认约束

- 原样保留 `#f0ffcf` 与 `#cef1f5` 两个品牌色值。
- 两个值与橙色主按钮背景的文字对比度低于 WCAG 普通文字建议值；这是经产品确认接受的品牌取舍，不在本次范围内改色。
- 保留首页的一条主路径：选择图片仍是唯一主操作。
- “更多制作方式”继续是轻量、可折叠的次级入口，不升级为弹窗、抽屉或阻塞式流程。
- 不改变上传、项目导入、已有图纸镜像、路由、存储或后端合同。
- 当前工作区已有未提交修改必须保留；本次改动只触及明确的 Token、首页入口样式、相关测试和文档所有者。

## 方案选择

采用“稳定锚点 + 原位展开”。

未采用的方案：

- 绝对定位 Popover 虽可做到零布局占位，但会引入遮挡、滚动裁切、定位和焦点管理问题。
- 弹窗或底部 Sheet 会增加一次阻塞式操作，对单个次级入口过重，也会削弱首页主路径。

## Token 架构

### 权威源

在核心 Token 中注册两个具有独立语义的品牌前景色：

- 主色表面通用前景：`#f0ffcf`
- 主按钮前景：`#cef1f5`

主题 Token 分别引用这两个品牌值。语义 Token 暴露主操作前景，组件 Token 的 `button.primary.foreground` 引用主操作前景，而 `color.text.onPrimary` 继续承担品牌标记、上传主入口等通用主色表面的前景。

这两个值必须保持独立，不能继续让按钮前景隐式继承 `color.text.onPrimary`，否则无法表达已确认的品牌差异。

### 生成物

运行现有 `pnpm generate:tokens` 统一更新：

- `src/design/generated/tokens.css`
- `src/design/generated/tokens.ts`
- 后端生成 Token 文件（仅在生成内容实际变化时）

生成后的 CSS 必须包含：

```css
--color-text-on-primary: #f0ffcf;
--button-primary-foreground: #cef1f5;
```

后续以 `pnpm check:tokens` 阻止再次出现手工生成物漂移。

## 首页布局与组件设计

### 布局所有权

- `app-shell` 继续拥有视口高度。
- `main-workspace` 继续作为受限的路由内容区域。
- `start-workspace` 继续是首页唯一的纵向滚动所有者。
- 不新增嵌套纵向滚动区域。

### 桌面稳定锚点

桌面断点不再通过内容总高度垂直居中 `start-workspace`。改为从一个响应式、受上下限约束的固定起点开始布局，使关闭状态保持当前视觉重心，同时保证展开后：

- 标题不移动；
- 主上传入口不移动；
- “打开已保存项目”不移动；
- “更多制作方式”的摘要行不移动；
- 新增内容只向下展开，隐私说明随正常文档流下移。

短视口下，响应式起点缩小，超出内容由 `start-workspace` 自身滚动，不依赖意外的 `body` 滚动。

### 移动端行为

移动端维持顶部起排和单一页面滚动。展开内容自然向下进入文档流，不使用浮层，也不制造同轴嵌套滚动。阅读顺序和焦点顺序与 DOM 保持一致。

### 展开面板视觉

继续使用原生 `<details>` / `<summary>`：

- 收起状态维持轻量次级入口。
- 展开内容与摘要属于同一个表面，通过分隔线和轻微背景层次区分。
- “镜像已有图纸”改为一体化操作行，不再表现为外层卡片中嵌套第二张卡片。
- 图标、标题和说明保持清晰的横向信息层级；整行可点击。
- 保留键盘展开、键盘激活、可见焦点和可访问名称。
- 仅保留现有箭头旋转及轻量颜色反馈，不添加高度动画；`prefers-reduced-motion` 下继续禁用过渡。

## 控制台警告处置

### 根因结论

`quick-panel.js` 不属于本仓库：

- 源码中不存在该文件或引用；
- `node_modules` 与锁文件中不存在该文件或引用；
- 当前生产构建产物中不存在该文件或引用；
- 应用源码没有 `unload` 监听器。

因此最合理的来源是浏览器扩展、浏览器侧栏或宿主环境注入脚本。警告与 Chrome 逐步停用 `unload` 事件的行为一致。

### 处理原则

- 不添加 `Permissions-Policy: unload=*`，避免为了第三方注入脚本重新启用不可靠的生命周期事件。
- 不改动应用现有 `beforeunload` 清理逻辑来伪装修复，因为它不是错误所指向的脚本或事件。
- 使用无扩展的干净浏览器上下文验证应用控制台；若干净上下文无警告，则记录为外部注入，不作为应用缺陷。
- 若普通浏览器上下文仍出现警告，通过 DevTools 中脚本完整 URL 识别具体扩展，由浏览器环境移除或更新该扩展。

## 测试与验收

### 自动化验证

- Token 生成后运行 `pnpm check:tokens`，确认生成物与权威源一致。
- 增加或调整窄范围测试，确认首页仍使用原生 `<details>`、保持唯一主上传入口，并保留“镜像已有图纸”入口。
- 增加样式回归断言，防止桌面断点重新引入基于内容高度的垂直居中，并确认展开项使用一体化表面结构。
- 运行受影响测试、TypeScript、ESLint、Prettier 和生产构建；最终运行完整 `pnpm check`。

### 浏览器验收

至少验证以下状态：

- 桌面宽屏：关闭与展开前后，标题、上传入口、项目入口和摘要行的位置保持稳定。
- 桌面短视口：展开后内容可由首页单一滚动区域访问。
- 390px 移动端：展开向下生长、无横向溢出、无嵌套滚动。
- 键盘：摘要可聚焦并用 Enter/Space 展开；操作行焦点清晰；收起后焦点顺序合理。
- 减少动态效果：箭头和颜色过渡被禁用。
- 干净浏览器上下文：应用控制台没有来自应用构建的 `unload` Permissions Policy 警告。

## 非目标与残余风险

- 不调整已确认的两个品牌色值。
- 不重新设计预览、编辑器或 GrabCut 工作区。
- 不修改浏览器扩展或宿主注入脚本。
- 品牌色对比度偏低仍是明确接受的可访问性风险。
- 普通浏览器环境若继续注入 `quick-panel.js`，警告只能由对应扩展或宿主环境消除；应用无法可靠屏蔽第三方脚本的控制台信息。
